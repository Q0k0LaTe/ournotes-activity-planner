# 活动 #1 计算验证（2026-10-05）

## 目标与公式

活动 #1 的活动 SR 奖励分别在累计 100,000、150,000、200,000、300,000、675,000 PT 发放；拿齐五张所需目标是 **675,000 PT**。[haneoka 活动页](https://haneoka.org/intl/zh-CN/events/1/)与固定 Master 奖励表相符。

给定歌曲评级 `rank` 和合法的 Boost／CP 消耗，单场计算为：

```text
活动 PT = floor(该模式该评级的 PT 基础值 × 消耗倍率 × (10000 + 成员活动 PT 加成) / 10000)
活动徽章 = Σ floor(每条保底徽章奖励基础值 × 消耗倍率 × (10000 + 留影徽章加成) / 10000)
普通演出获得 CP = 该评级 CP 基础值 × 消耗倍率
```

活动 PT 与活动徽章均受评级和消耗倍率影响，但取自**不同卡牌加成**。不能用活动 PT 加成直接推算徽章。活动 PT 是累计 SR 奖励的进度，徽章是交换所资源。固定 Master 的普通评级 D/C/B/A/S/SS 基础 PT 是 15/25/35/50/75/100，基础徽章是 18/30/42/60/90/120；挑战基础 PT 是 1500/2000/2550/3250/3900/5000，基础徽章是 1450/2650/3400/3750/4450/4950。普通 Boost 1–10 的倍率是 5–50；挑战 CP 200/400/800/1600 的倍率是 1/2/4/8。[公开计算模型](https://github.com/empty-sekai/ournotes-deck/blob/dbd9cf01a4854808dceb6aedcd4041af372faeee/src/event.rs)与上述固定表用于本地预估。

例：普通 C、4 Boost、成员 PT 加成 +70%、留影徽章加成 +90%，得到 `25×20×1.7 = 850 PT`、`30×20×1.9 = 1140 徽章`、`4×20 = 80 CP`。把徽章加成改成 0%，PT 仍为 850，徽章降为 600。

## 跳过规则与配队目标

- **普通演出跳过固定 C**。游戏内帮助 `Help_SubCategory_Description_100002` 明确规定，跳过以 C 评级奖励结算，不计歌曲通关，也不更新最高分。模型仍可算一个参考分数，但不能据此提高或降低跳过的奖励评级；活动 PT、徽章和 CP 均使用 C 档。跳过仅适用于普通演出。
- **不指定歌曲**：普通跳过的奖励评级已经确定，固定 Boost 和同一活动下可直接比较每局 PT；普通 AP 与挑战演出的评级还取决于谱面、卡组和养成，单看加成不能确定最优。
- **指定歌曲刷累计 PT**时，搜索已勾选且满足限制的五人队伍与留影绑定，按单场预计 PT 排序；同 PT 再比较徽章、参考分数和综合力。挑战门票**凹榜分**选择理论分数目标。AP 使用 120 种技能顺序中的最低估算分数与保守评级。
- **纠正此前的跳过实验**：普通歌曲 #100039 Expert 跳过、4 Boost、同队长与留影绑定。成员 #38（Lv20）队伍的模型参考分为 C、加成 +80%、900 PT；换成 #63（Lv1）后参考分为 D、加成 +105%，但**奖励仍是 C，得到 1,025 PT**。以前把后者误算为 D／615 PT，导致了错误的配队排序。
- **挑战门票目标实验**：合成六成员池、挑战歌曲 #100109 Expert 理论 AP、200 CP。理论分数目标选 `[11,26,38,55,59]`，最低估算分 1,484,714、C 评级、3,600 PT；单场 PT 目标选 `[11,26,55,59,63]`，最低估算分 1,463,615、C 评级、4,100 PT。凹分和刷累计奖励可能使用不同队伍；如可同时达到目标累计 PT，剩余门票可用于凹分。
- **拉表**根据普通每局 PT／徽章／CP 与挑战每局 PT／徽章／CP 消耗，找出同时达到 PT 与可选徽章目标所需的最少普通场次；再用足够少的挑战场次完成目标，保留未用 CP。每日表与 CSV 展示预计累计 PT、徽章、剩余 CP。这里按输入的固定每局收益计算，不自动加上累计奖励里的额外徽章，也不假设未来每场都能达到同样评级。

## 已做核对与边界

`test_event_rewards.py` 核对公开评级基础值、全部 10 档普通 Boost 和 4 档挑战 CP 倍率、三组不同加成及 PT／徽章独立性。`test_song_optimizer.py` 在小卡池直接穷举每一种留影绑定，检查普通跳过固定 C 的 PT／徽章最优和挑战 AP 的 PT 最优，并保存上述实验。`test_power_modes.py` 检查普通跳过在旧搜索器与 CP-SAT 搜索器中都报 C。`event_math.test.cjs` 检查双目标场次、CP 守恒、每日累计和无法达标的输入。浏览器静态页面已实测普通 PT 搜索、挑战分数搜索与双目标拉表；双目标样例得到 3 场普通、2 场挑战、13,000 累计 PT、120 累计徽章、剩余 100 CP。更多固定卡组实验见 [玩家说法验证](CLAIM-EXPERIMENTS.md)。

验证范围是 **2026-10-01 日服数据、活动 #1，并单独补入成员 #64** 的客户端参考模型。普通演出不计活动参数加成，挑战演出计入。分数计算假设 AP/PERFECT、正生命值、辅助与撃奏关闭。已有历史实机结算只校对过一个普通样本和一个已知队伍的挑战 B 样本，不能用来独立验证所有倍率与取整路径。本轮没有新的实机结算图。故本文的“最优”是**当前输入卡池与该模型内**的结论，不能承诺每一局真实结算绝对一致。若有实机差异，应保存结算画面或数值，并把实测每局收益填入活动拉表。
